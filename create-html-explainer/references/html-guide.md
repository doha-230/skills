# HTML 설명자료 만들기

## 목적

독자가 개념을 이해하고, 예제를 따라가고, 필요한 경우 입력값을 바꾸어 결과를 확인할 수 있는 HTML 설명자료를 만든다. 기술, 인문, 사회, 일상 지식 등 분야를 제한하지 않는다. 계산이 없는 주제에도 적용한다.

기본 결과물은 브라우저에서 바로 열 수 있는 UTF-8 단일 HTML 파일이다. 별도 서버, 빌드, 설치 없이 사용하게 한다. 사용자가 기존 프로젝트 수정을 요청하면 그 프로젝트의 구조를 따른다.

## 내용 구성

사용자가 제공한 내용, 목적, 독자 수준과 기존 자료를 우선한다. 독자가 지정되지 않으면 해당 주제를 처음 접하는 일반 독자를 기준으로 쓴다. 설명 언어는 사용자 요청을 따르고, 지정이 없으면 대화에서 사용한 언어를 따른다. 맥락도 없으면 한국어를 사용한다. 결과를 크게 바꾸는 정보가 부족할 때만 질문하고, 나머지는 합리적인 기본값으로 진행한다.

이 지침은 통합 스킬의 설명형 HTML 산출물에 적용한다. 시각 탐색형 산출물은 별도 파일로 함께 만들며, 그 상세 지침은 visual-explainer.md를 따른다. 기존 예제 파일을 필수 의존성으로 삼지 않는다.

다음 흐름에서 주제에 필요한 부분을 선택한다. 모든 항목을 억지로 채우지 않는다.

1. **제목과 핵심 설명:** 무엇을 설명하는지, 어디에 쓰이는지 첫 화면에서 알 수 있게 한다.
2. **핵심 개념:** 주요 관계, 원리, 수식 또는 절차를 크게 보여준다.
3. **용어와 기호:** 뜻, 단위, 역할을 표나 간결한 설명으로 정리한다.
4. **구체적인 예제:** 조건 → 계산 또는 과정 → 결과 → 해석 순서로 보여준다.
5. **탐색 도구:** 이해에 도움이 되면 계산기, 조절 가능한 그래프, 비교 선택 또는 단계 전환을 제공한다.
6. **적용 범위:** 가정, 실제 적용 조건과 모델의 한계를 설명한다.
7. **출처:** 자료에 사용한 문서와 참고 링크를 넣는다.

수식이 없는 주제는 핵심 개념을 도식, 사례, 순서도 또는 비교표로 표현한다. 계산할 내용이 없으면 계산기를 만들지 않는다. 정적 설명으로 충분하면 인터랙션을 추가하지 않는다.

## 설명의 정확성

- 이름이나 표기가 모호하면 문맥과 신뢰할 수 있는 자료로 식별한다. 설명 대상이 달라질 정도의 모호함이 남으면 사용자에게 확인한다.
- 최신성 또는 전문 지식의 확인이 필요한 내용은 공식 문서, 저자의 자료, 표준 원문, 원 논문 등으로 확인한다.
- 출처가 있는 값과 설명용 가상 값을 구분한다. 가상 값은 입력 영역과 예제 근처에 표시한다.
- 수식의 변수, 단위, 허용 범위와 가정을 함께 설명한다. 계수와 비슷한 이름의 물리량을 혼동하지 않는다.
- 입력값 변경으로 계수의 단위나 전제 조건이 달라지면 그 관계를 명시한다.
- 계산기와 그래프는 같은 모델 및 단위를 사용한다. 출력에는 숫자, 단위와 의미를 함께 표시한다.
- 검증하지 않은 출처, 인증, 규격 적합성을 주장하지 않는다.

## 문체와 언어

짧고 명확한 문장으로 한 문장에 한 가지 생각을 전달한다. 기술 용어는 먼저 정의하고, 같은 개념에는 같은 명칭을 사용한다. 쉬운 말로 설명하되 중요한 조건을 생략하지 않는다.

사용자가 요청한 언어와 독자 수준에 맞춰 설명한다. 번역이나 다국어 자료를 요청하면 같은 내용을 대응시켜 배치하되, 요청하지 않은 언어 영역을 자동으로 추가하지 않는다.

특정 문체나 작성 규격을 요청하면 적용 범위와 실제 규칙을 확인한다. 규격을 참고하는 것과 준수 여부를 검증하는 것을 구별하고, 확인하지 않은 준수를 주장하지 않는다.

## 시각적 형식

사용자 지정 디자인, 브랜드와 기존 프로젝트의 스타일을 우선한다. 별도 지정이 없으면 주제와 독자에게 맞는 읽기 쉬운 디자인을 선택한다. 다음 수치는 시작점이며 고정 규격이 아니다.

- 최대 본문 폭은 약 1,100px, 바깥 여백은 데스크톱 24px, 모바일 16px로 한다.
- 배경, 본문, 강조색에 충분한 대비를 확보한다. 밝은 테마와 어두운 테마 중 맥락에 맞게 선택하고, 특정 팔레트를 강제하지 않는다.
- 제목은 약 30–48px, 본문은 약 16px, 줄 간격은 1.6–1.8로 한다. 설명 언어를 지원하는 시스템 글꼴을 사용한다.
- 제목, 여백과 필요한 구분선으로 정보의 위계를 표현한다. 카드와 둥근 모서리는 내용 묶음에 도움이 될 때 사용한다.
- 수식이나 핵심 관계를 크게 보여주고, 용어는 표로 정리한다. 계산기는 입력 영역과 결과 그래프를 데스크톱에서 나란히 배치하고 모바일에서는 세로로 쌓는다.
- 강조색은 핵심 값과 실제 데이터 표시에 사용한다. 색만으로 의미를 전달하지 않는다.
- 인쇄 시 장식 배경과 불필요한 버튼을 줄이고 주요 내용의 페이지 중간 분할을 최소화한다.

## 구현

- `<!doctype html>`, 언어 속성, UTF-8 선언과 viewport를 포함한다. CSS와 JavaScript는 기본적으로 파일 안에 넣는다.
- 외부 라이브러리와 글꼴 없이 작동하도록 우선 설계한다. 외부 의존성이 필요한 경우 그 이유와 인터넷 연결 조건을 명시한다.
- 단순한 수식은 접근 가능한 HTML 또는 MathML로 표현한다. 외부 수식 렌더러가 없어서 원시 수식 문자열이 그대로 보이지 않게 한다.
- 단순한 도식과 그래프는 SVG로 구현한다. 축 이름, 단위, 주요 값과 텍스트 대체 설명을 제공한다.
- 모든 입력에 보이는 라벨을 붙이고, 수치 입력에는 해당 단위를 표시한다. 키보드 조작과 초점 표시를 지원한다. 결과 변경은 필요한 경우 `aria-live`로 알린다.
- 빈 값, 잘못된 범위, 0으로 나누기, 비유한 계산 결과를 처리한다. 오류가 발생하면 이전 결과와 그래프를 지우고 수정할 조건을 가까이 표시한다.
- 실시간 계산에는 합리적인 초기값과 초기화 버튼을 제공한다. 입력을 바꾸면 숫자와 그래프가 함께 갱신되게 한다.
- 반올림은 표시 단계에서 수행한다. 계산은 원래 정밀도로 유지한다.
- 사용자 입력이나 외부 텍스트는 `textContent` 등으로 표시한다. 검증되지 않은 문자열을 `innerHTML`에 삽입하지 않는다.

## 저장과 확인

사용자가 지정한 위치에 저장한다. 지정하지 않았으면 현재 작업 폴더에 주제를 나타내는 짧은 파일명으로 저장한다. 기존 자료를 수정하는 요청이면 해당 파일과 구조를 따른다. 새 자료 생성 시 같은 이름의 파일이 있으면 다른 이름을 선택한다. 관련 없는 기존 파일은 수정하지 않는다.

완료 전에 실제로 포함한 내용과 기능에 해당하는 항목을 확인한다.

- 문서의 설명, 예제, 계산 결과와 단위가 서로 일치하는가?
- 기본 예제를 독립 계산했을 때 결과가 맞는가?
- 인터랙션이 있다면 정상 입력, 경계값, 잘못된 입력, 초기화를 처리하는가?
- 모바일 폭에서 표, 수식, 그래프와 버튼이 읽기 어렵게 잘리거나 겹치지 않는가?
- 출처와 접근성 설명이 실제 내용에 대응하는가?

가능하면 브라우저에서 데스크톱과 모바일 화면을 확인한다. 브라우저 확인을 못 했으면 코드나 계산 검증만으로 시각 검증까지 완료했다고 주장하지 않는다. 정적 페이지에는 불필요한 테스트 파일을 추가하지 않는다.

최종 응답에는 생성한 HTML의 클릭 가능한 파일 링크와 포함한 내용을 짧게 안내한다. 실제로 실행한 검증만 보고한다. 게시나 전역 스킬 설치는 사용자가 요청한 경우에만 수행한다.

## 사용 예

- “처음 배우는 사람을 위한 개념 설명을 HTML로 만들어 줘.”
- “이 수식을 변수 설명, 계산 예제와 그래프가 있는 HTML로 만들어 줘.”
- “두 방법의 차이를 비전공자에게 설명하는 HTML 자료를 만들어 줘.”
- “이 절차를 단계별 HTML 안내 자료로 만들어 줘.”

이 문서는 통합 스킬의 상세 지침이다. 특정 예제 파일, 브랜드 또는 플러그인에 의존하지 않는다.
