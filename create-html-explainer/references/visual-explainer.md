# 인터랙티브 HTML 설명자료

이 지침은 통합 스킬의 시각 탐색형 산출물에 적용한다. 설명형 HTML과 별도 파일로 함께 만들며, 전체 작업의 생성·전달 조건은 상위 SKILL.md를 따른다.

읽는 사람이 조작하면서 개념과 관계를 이해하는 자료를 만든다. 설명과 그림을 장식으로 나란히 두지 말고, 같은 개념과 상태를 서로 다른 표현으로 보여 준다. 기술, 인문, 사회, 일상 지식 등 분야를 제한하지 않는다. 수식이 없는 주제는 사례, 흐름, 분류, 비교 또는 선택에 따른 변화를 연결한다.

## 기본 결과물

- 사용자가 다른 형식을 지정하지 않았다면, UTF-8로 저장한 단일 `.html` 파일을 만든다. `<!DOCTYPE html>`, `lang`, 문자 인코딩, 반응형 viewport를 포함한다.
- 독립형 자료는 CSS, JavaScript, 도식을 파일에 포함해 오프라인에서 동작하도록 한다. 외부 의존성이 필요한 요청이면 이유와 연결 조건을 명시한다. 기존 프로젝트 수정 시 해당 구조와 도구를 따른다.
- 대상 독자, 용어 수준, 색상, 언어, 분량은 사용자의 요청을 우선한다. 설명 언어를 지정하지 않으면 대화의 언어를 따르고, 맥락도 없으면 한국어를 사용한다.
- 작업 폴더에 주제를 나타내는 파일명으로 저장한다. 기존 자료를 수정하라는 요청이 아니라면 기존 파일을 덮어쓰지 않는다.
- HTML 생성 요청만으로 호스팅이나 공개 게시까지 수행하지 않는다.

## 설명을 설계하는 순서

### 1. 독자가 이해해야 할 관계를 정한다

주제를 하나의 질문으로 좁힌다. 예: “입력을 두 배로 하면 결과는 어떻게 바뀌는가?”, “어떤 조건에서 두 방법의 결과가 달라지는가?”

사용자가 제공한 설명과 자료를 먼저 읽는다. 내용이 충분하면 바로 진행하고, 대상 독자나 모델의 선택이 결과를 크게 바꿀 때만 필요한 정보를 묻는다. 독자가 지정되지 않으면 해당 주제를 처음 접하는 일반 독자를 기준으로 필요한 기초 개념부터 소개한다.

조작이 이해에 어떤 도움을 주는지 먼저 정한다. 입력 변화, 사례 비교, 과정 진행, 조건 선택 중 적합한 방식을 고른다. 정적인 설명으로 충분하면 정적 자료로 구성하고 불필요한 인터랙션을 만들지 않는다. 일반 설명형 스킬이나 기존 예제 파일을 필수 의존성으로 삼지 않는다.

전문 수식·알고리즘·실험 모델의 사실관계는 공식 문서, 원논문, 저자 자료 등 일차 자료로 확인한다. 사용자가 지정한 출처를 우선한다. 확인하지 못한 사실을 검증했다고 쓰거나, 그럴듯한 DOI·참고문헌·수치를 만들지 않는다.

### 2. 직관에서 원리로 이어지는 흐름을 만든다

아래 흐름을 주제에 맞게 조합한다. 모든 주제에 같은 단계 수를 강제하지 않는다.

1. 관찰 가능한 현상 또는 작은 문제를 보여 준다.
2. 한 입력을 바꿔 결과의 변화를 보여 준다.
3. 그 관계를 식이나 규칙으로 표현한다.
4. 구성 요소, 변수 또는 조건의 역할을 하나씩 분리한다.
5. 전체 관계로 돌아와 예측하거나 비교한다.
6. 실제 적용과 설명의 한계를 연결한다.

각 단계는 하나의 질문에 답하도록 한다. 짧은 문장으로 현상 → 관계 → 이유를 설명한다. 새 용어나 기호는 그것을 사용하는 추론보다 먼저 소개한다. 시각 요소를 보면 알 수 있는 내용을 길게 반복하지 않는다.

### 3. 하나의 상태를 여러 표현에 연결한다

중앙 상태와 공통 계산 또는 변환 규칙을 두고 설명, 도식, 그래프와 결과가 같은 상태로 갱신되게 한다. 같은 규칙을 여러 화면 요소에서 따로 구현하지 않는다. 수식·그래프·결과 숫자는 해당 주제에 필요할 때만 사용한다.

- 조작에는 슬라이더, 선택 버튼, 단계 선택 또는 숫자 입력 중 적합한 것을 제공한다.
- 같은 변수나 개념의 입력, 설명, 그림의 표식, 그래프의 축·곡선을 일관된 색과 이름으로 연결한다.
- 색만으로 의미를 전달하지 않는다. 이름, 기호, 선 모양, 단위도 붙인다.
- 현재 선택이나 입력과 그 결과를 눈에 보이게 표시한다. 정적 초기 화면에서도 설명이 성립해야 한다.
- 결과를 직접 계산하기 어려우면 검증 가능한 근사, 표본 데이터 또는 명시적인 개념 모형을 사용한다. 임의의 애니메이션을 실제 계산인 것처럼 보여 주지 않는다.

## 표현과 조작의 기본형

### 화면 구성

사용자 지정 테마, 브랜드와 기존 프로젝트의 스타일을 우선한다. 지정이 없으면 주제와 독자에게 맞는 밝은 테마 또는 어두운 테마를 선택한다. 넉넉한 여백, 읽기 쉬운 글자와 충분한 대비를 확보하고, 개념을 구별하는 데 필요한 색만 사용한다. 특정 팔레트나 브랜드의 표현 방식을 기본 조건으로 삼지 않는다.

다음 구성은 출발점이며 주제에 맞게 줄이거나 바꾼다.

- 제목과 핵심 질문.
- 단계 선택과 현재 단계의 짧은 설명.
- 색으로 의미를 연결한 핵심 식 또는 규칙.
- 현상 도식과 대응하는 그래프. 넓은 화면에서는 나란히, 좁은 화면에서는 세로로 배치한다.
- 주요 결과 숫자와 입력 조작부.
- 이전·다음, 초기화. 자동 설명이 학습에 도움이 되면 시작·정지 버튼을 추가한다.
- 변수 정의, 계산 예제, 적용 조건, 출처.

참고 스타일을 요청하면 색의 연결, 설명의 흐름, 시각적 위계 등 유용한 원칙을 추출해 주제에 맞게 적용한다. 참고 대상과의 공식 제휴를 암시하지 않는다.

### 그래프와 도식

- 단순한 도식과 그래프는 SVG를 우선한다. 데이터가 많거나 계산량이 큰 경우 Canvas 등 적합한 방식을 선택한다.
- 그래프에 축 이름, 단위, 현재 상태의 표식을 넣는다. 필요한 경우 비교 곡선과 범례를 제공한다.
- 변수 비교 시 축 범위를 가능하면 고정한다. 자동 축척으로 바꾸면 이를 알리고, 축척 변화가 물리적 변화처럼 보이지 않게 한다.
- 범위를 넘어선 값을 그림에 맞추려고 계산값까지 자르지 않는다. 시각적 축척 조정과 모델 계산을 분리한다.
- 모식도라면 축척, 화살표 길이, 형상이 실제 값에 비례하는지 밝힌다.
- 글자와 곡선, 수치 라벨과 가장자리가 겹치지 않도록 공간을 확보한다.

### 단계 이동과 애니메이션

- 단계형 자료에서는 단계를 직접 선택할 수 있게 하고, 이전·다음과 초기화를 제공한다. 단계 전환 시 현재 입력을 유지할지 예시 상태로 바꿀지 일관되게 정한다.
- 입력 변화는 값과 형상의 변화로 보여 준다. 단순 페이드나 설명과 무관한 반복 운동을 피한다.
- 애니메이션은 보통 200–500 ms의 짧은 전환으로 사용한다. 프레임마다 모델의 관계가 유지되도록 입력을 보간한 뒤 결과를 다시 계산한다.
- 자동 설명은 사용자가 시작할 때만 재생한다. 직접 조작하거나 정지하면 멈추고, 재시작 시의 동작을 버튼 이름과 일치시킨다.
- 초기화와 정지 시 타이머·애니메이션을 취소한다. 페이지가 비활성화되면 자동 설명을 멈춘다.
- `prefers-reduced-motion`을 존중하고, 애니메이션을 꺼도 모든 설명과 조작이 가능하게 한다.

## 내용과 모델의 정확성을 지키는 규칙

정성적 주제는 근거가 있는 사실, 해석과 가상 사례를 구별한다. 선택에 따른 결과를 단정하기 어렵다면 조건과 불확실성을 함께 보여 준다. 비교나 순서도에 계산 모델이 있는 것처럼 꾸미지 않는다. 아래 수치 모델 규칙은 계산이 있는 자료에 적용한다.

- 모든 기호의 뜻, 단위, 허용 범위와 기본값을 정의한다. 측정값, 문헌값, 교육용 가정값을 구별한다.
- 비교할 때 무엇을 고정했는지 명시한다. 같은 힘과 같은 압력, 같은 예산과 같은 단가, 같은 표본 수와 같은 정밀도는 서로 다른 비교다.
- 지수나 차원이 바뀌는 변수는 계수의 단위와 비교 기준도 검토한다. 필요하면 기준점으로 정규화하고, 원래 식으로의 환산을 설명한다.
- 계산에 사용하는 단위와 표시 단위를 구분하고 변환을 일관되게 적용한다.
- 로그, 나눗셈, 제곱근, 확률 등 정의역이 있는 계산은 입력을 검증한다. 오류나 범위 초과를 `NaN`, `Infinity`, 빈 화면으로 남기지 않는다.
- 예측식과 원식을 왕복 계산하거나 알려진 특수값으로 확인한다. 모델의 한계는 실제로 이 자료의 해석에 영향을 주는 것만 간결하게 설명한다.
- 실험식의 외삽, 교육용 단순화, 수치 근사, 불확실성을 결과와 혼동하지 않도록 표시한다.

## 접근성과 완성도

- 의미 있는 HTML 요소, 실제 버튼, 입력과 연결된 label을 사용한다. 키보드로 주요 기능을 조작할 수 있게 한다.
- 현재 단계와 선택 조건은 `aria-current`, `aria-pressed` 등으로 표현한다. 변화하는 핵심 결과는 필요하면 짧은 `aria-live` 설명을 제공하되 슬라이더를 움직이는 매 프레임마다 읽히게 하지 않는다.
- SVG·Canvas에는 내용을 요약하는 접근성 설명을 제공한다.
- 좁은 화면에서 본문·수식·버튼이 잘리지 않도록 한다. 긴 식은 줄바꿈이나 해당 영역의 스크롤 등으로 처리한다.
- JavaScript를 사용할 수 없는 경우에도 핵심 설명, 용어와 대표 예제는 읽을 수 있게 한다.
- 코드나 개발 절차를 학습 화면에 노출하지 않는다. 사용자 이해에 필요한 모델의 가정과 범위는 설명한다.

## 검증과 전달

규모에 맞게 실제로 포함한 내용과 기능에 해당하는 항목을 확인한다.

1. 대표 예제와 결과가 일치하고, 입력이나 선택을 바꾸면 관련 설명과 시각 표현이 함께 바뀌는지 확인한다. 계산이 있다면 독립 계산으로 확인한다.
2. 대표적인 경계값, 비교 조건 전환, 단계 이동, 초기화, 자동 설명의 시작·정지를 확인한다.
3. 계수와 단위, 그래프 축, 비교 기준, 출처 링크가 일치하는지 확인한다.
4. 가능하면 브라우저에서 넓은 화면과 좁은 화면을 확인한다. 겹침·넘침·런타임 오류를 수정한다.
5. 브라우저 확인이 불가능하면 계산·스크립트 검증을 수행하고, 실제 화면을 확인한 것처럼 보고하지 않는다. 형식 검사나 모의 DOM 실행을 화면 렌더링 검증과 구별한다.

추가 검증 코드는 필요할 때만 작성한다. 출처는 HTML 안에서 해당 설명 근처 또는 참고자료 영역에 실제 링크로 남긴다. 완성 파일을 다시 읽어 인코딩과 미완성 문구를 확인한다.

마지막 응답에는 HTML 파일 링크, 핵심 조작 방법, 중요한 검증 제한만 짧게 안내한다. 새 주제로 요청받으면 이전 예제의 변수·문헌·수치를 그대로 가져오지 말고 해당 주제에 맞게 새로 구성한다.
