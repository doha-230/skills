# 설명형·시각 탐색형 HTML 함께 만들기

같은 주제를 읽으며 이해하는 자료와 시각적으로 탐색하는 자료로 각각 만든다. 기존 `create-html-explainer`와 `visual-explainer`의 기능을 이 스킬 하나에서 수행한다. 기술, 인문, 사회, 일상 지식 등 분야를 제한하지 않는다.

## 필수 산출물

스킬을 사용할 때 기본적으로 아래 **두 파일을 모두** 생성하고 검증한다. 주제에 따라 한쪽만 선택하거나 하나의 HTML에 두 영역을 넣는 것으로 완료하지 않는다.

| 산출물 | 기본 파일명 | 목적과 구성 |
| --- | --- | --- |
| 설명형 HTML | `<topic>-guide.html` | 읽으며 배우는 자료. 핵심 설명, 용어·기호, 구체적인 예제, 과정·계산의 해석, 적용 범위와 출처를 주제에 맞게 구성한다. 계산기나 그래프는 이해에 도움이 될 때 넣는다. |
| 시각 탐색형 HTML | `<topic>-visual.html` | 그림과 설명으로 관계를 이해하는 자료. 입력 변화, 사례 비교, 단계 이동 또는 조건 선택을 관련 설명·도식·그래프·결과와 연결한다. 정적 시각 설명으로 충분한 주제는 관계·과정·비교를 중심으로 구성한다. |

두 파일은 각각 독립적으로 열고 사용할 수 있어야 한다. 같은 파일의 복사본에 제목이나 색만 바꿔 두 결과물로 제출하지 않는다. 시각 탐색형은 설명형의 긴 본문을 반복하기보다 핵심 관계와 변화에 집중한다. 두 파일의 주제, 용어, 가정, 예제의 기준값, 단위와 출처는 일치시킨다.

사용자가 명시적으로 한쪽만 요청하거나 산출물 형식을 제한하면 그 요청을 우선한다. 그 외에는 정적 설명으로 충분하다는 판단을 한쪽 산출물을 생략하는 이유로 삼지 않는다. 인터랙션·수식·계산·애니메이션은 필요한 경우에만 넣고, 조작이 필요 없는 주제에도 별도의 시각 설명 파일을 만든다.

## 상세 지침

작업 시작 시 아래 **두 문서를 모두 읽는다**. 이 파일은 공통 요구사항과 완료 조건을 정하고, 각 문서는 해당 산출물의 설계·구현·검증을 구체화한다. 상세 지침의 단일 파일·결과물 선택·최종 전달에 관한 문구는 각 산출물에 개별적으로 적용하며, 전체 작업은 이 파일의 두 산출물 생성·전달 조건을 따른다.

- [설명형 HTML 상세 지침](references/html-guide.md): 내용 구성, 쉬운 문장, 예제, 인쇄와 읽기 중심의 형식.
- [시각 탐색형 HTML 상세 지침](references/visual-explainer.md): 직관에서 원리로 이어지는 흐름, 상태 연동, 도식·그래프, 단계 전환과 애니메이션.

별도로 설치한 원본 스킬이나 특정 예제 파일에 의존하지 않는다. 통합 스킬 폴더 전체를 옮기면 사용할 수 있다.

## 공통 작업 흐름

1. 사용자 자료와 요청에서 주제, 목적, 독자 수준, 언어와 저장 위치를 확인한다. 독자가 없으면 처음 접하는 일반 독자를 기준으로 하고, 언어는 대화의 언어를 따른다. 맥락도 없으면 한국어를 사용한다. 결과를 크게 바꾸는 모호함만 질문한다.
2. 두 자료가 공유할 핵심 개념, 용어, 예제, 가정과 출처를 정한다. 최신성이나 전문 지식의 확인이 필요한 사실은 공식 문서, 원논문, 저자 자료 등 일차 자료로 확인한다. 확인하지 않은 수치나 참고문헌을 만들지 않는다.
3. 설명형 자료의 읽기 흐름과 시각 탐색형 자료의 핵심 질문·표현을 각각 설계한다. 정성적 주제는 사례, 흐름, 분류 또는 비교로 표현하며 계산 모델이 있는 것처럼 꾸미지 않는다.
4. 두 HTML을 각각 구현한다. 수치 모델이 있다면 동일한 식과 단위를 적용한다. 각 파일 안에서는 공통 계산·변환 규칙과 중앙 상태를 두어 입력, 설명, 도식, 그래프와 결과가 함께 갱신되게 한다.
5. 두 파일을 각각 검증하고, 서로의 설명·예제·값·단위·출처가 일치하는지 확인한다. 한쪽 파일이 완성되었다고 작업을 끝내지 않는다.
6. 두 파일의 클릭 가능한 링크, 각 자료의 역할과 핵심 조작 방법을 짧게 전달한다. 실행한 검증과 중요한 검증 제한만 보고한다.

## 구현과 저장

- 기본적으로 UTF-8 단일 HTML **두 개**를 만든다. 각각 `<!doctype html>`, `lang`, UTF-8 선언과 반응형 viewport를 포함하고, CSS·JavaScript·도식을 내장해 서버·빌드·설치 없이 오프라인으로 사용하게 한다. 외부 의존성이 필요한 요청이면 이유와 연결 조건을 명시한다.
- 사용자 지정 테마와 기존 프로젝트의 구조를 우선한다. 지정이 없으면 읽기 쉬운 글자, 충분한 대비와 여백을 확보하고 데스크톱·모바일에 대응한다.
- 단순 도식·그래프에는 SVG를 우선하고, 수식에는 접근 가능한 HTML 또는 MathML을 사용한다. 이름, 단위와 텍스트 설명을 함께 제공하며 색만으로 의미를 전달하지 않는다.
- 입력에는 보이는 label과 단위를 붙인다. 키보드 조작, 초점 표시와 필요한 결과 알림을 지원한다. JavaScript 없이도 핵심 설명과 대표 예제를 읽을 수 있게 한다.
- 계산은 원래 정밀도를 유지하고 표시할 때 반올림한다. 빈 값, 잘못된 범위, 정의역 오류와 비유한 결과를 처리하고 오류 시 이전 결과가 유효한 것처럼 남지 않게 한다. 사용자 입력·외부 텍스트는 `textContent` 등으로 표시한다.
- 사용자 지정 위치에 저장하며, 위치가 없으면 현재 작업 폴더를 사용한다. 새 파일의 이름이 겹치면 두 자료의 주제 접두사를 일관되게 바꾼다. 기존 자료 수정 요청은 해당 파일을 수정하고 대응 산출물이 없으면 함께 만든다. 관련 없는 파일은 수정하지 않는다.
- 두 파일이 같은 폴더에 있으면 상대 경로로 서로 이동하는 링크를 제공한다. 링크 없이도 각각의 핵심 설명과 기능은 성립해야 한다.
- 생성 요청만으로 게시, 호스팅 또는 전역 스킬 설치를 수행하지 않는다.

## 완료 조건

- 사용자 제한이 없다면 서로 다른 목적의 HTML 두 파일이 실제로 존재하고, 각각 단독으로 열 수 있는가?
- 두 자료의 핵심 설명, 용어, 예제, 가정, 값과 단위가 서로 일치하는가? 계산이 있다면 대표 예제를 독립 계산했는가?
- 각 파일에 실제로 포함한 조작의 정상 입력, 경계값, 잘못된 입력, 단계 이동, 초기화와 시작·정지가 동작하는가?
- 두 파일 모두 가능하면 브라우저에서 넓은 화면과 좁은 화면을 확인하고 겹침·넘침·런타임 오류를 수정했는가?
- 출처 링크, 파일 간 이동 링크, 접근성 설명, UTF-8 인코딩과 미완성 문구를 확인했는가?

브라우저를 사용할 수 없으면 가능한 코드·계산 검증을 수행하고 시각 검증의 제한을 명시한다. 정적 자료에 불필요한 테스트 파일을 추가하지 않는다. 한쪽 산출물을 만들지 못했다면 이유와 남은 작업을 밝히고, 두 자료가 모두 완성된 것으로 보고하지 않는다.

## 사용 예

- “$create-html-explainer로 처음 배우는 사람을 위한 개념 자료를 만들어 줘.”
- “이 수식을 설명자료와 조작 가능한 시각 자료로 함께 만들어 줘.”
- “두 방법의 차이를 비전공자가 읽고 비교해 볼 수 있게 HTML로 만들어 줘.”
- “이 절차의 단계별 안내와 시각 탐색 자료를 만들어 줘.”
