사용설명서

Word, PowerPoint, Excel을 폐쇄망 Windows에서 직접 제어합니다. 설치부터 MCP 연결, 문서 확인, 오류 해결까지 순서대로 따라가세요.

Windows 64비트Python 3.11Word · PowerPoint · Excel로컬 stdio

MCP 클라이언트가 로컬 Python 서버에 도구 호출을 보내면, 서버가 Windows COM을 통해 설치된 Office 앱을 조작합니다.

폐쇄망 동작

문서 처리에 인터넷이나 API 키가 필요 없습니다. 인터넷 사진 검색 도구는 제거했습니다. 이미지는 로컬 파일을 ppt_add_image로 넣습니다.

준비물과 파일 구성

항목필요한 상태
운영체제Windows 10/11 64비트
Office데스크톱 Microsoft Office 2019 이상. 사용할 Word·PowerPoint·Excel 앱이 설치되어 있어야 합니다.
PythonPython 3.11 64비트, venv와 pip 포함. 기본 설치 스크립트는 Python Launcher py를 사용합니다.
MCP 클라이언트로컬 stdio MCP 서버를 등록·실행할 수 있는 클라이언트

office-com 폴더 전체를 복사해야 합니다. server.py와 bridge/는 실행 코드, wheelhouse/win_amd64_py311/에는 30개 Windows용 wheel, install-offline.ps1은 오프라인 설치 스크립트입니다.

설치 매체

Python과 Office 설치 프로그램은 이 폴더에 들어 있지 않습니다. 폐쇄망 PC에 미리 설치하거나 별도 매체로 준비하세요. wheel은 Python 3.11 64비트 Windows용입니다.

폐쇄망 PC에 설치하기

1
폴더를 통째로 복사예를 들어 C:\OfficeMCP\office-com에 복사합니다. wheelhouse를 포함해야 합니다.
2
PowerShell에서 설치 실행설치 스크립트는 wheel 해시를 확인한 뒤 인터넷 인덱스를 사용하지 않고 설치합니다.
cd C:\OfficeMCP\office-com
powershell -ExecutionPolicy Bypass -File .\install-offline.ps1

Python Launcher가 없으면 -PythonExe "C:\경로\python.exe"를 명령 끝에 추가하세요.

3
완료 메시지 확인스크립트가 .venv를 만들고 pywin32를 등록한 뒤 MCP 도구 등록을 확인합니다.
.\.venv\Scripts\python.exe .\verify-windows.py
직접 설치할 때

가상 환경을 이미 만들었다면 pip install --no-index --find-links .\wheelhouse\win_amd64_py311 -r .\requirements.txt를 사용합니다. 자세한 명령은 wheel 안내를 보세요.

MCP 클라이언트에 연결하기

클라이언트에 실행 명령과 인수를 등록합니다. 아래는 mcpServers 형식의 설정 예입니다. 설치 위치에 맞게 절대 경로를 바꾸고, 해당 클라이언트의 MCP 설정 형식에 넣으세요.

{
  "mcpServers": {
    "office-com": {
      "command": "C:\\OfficeMCP\\office-com\\.venv\\Scripts\\python.exe",
      "args": ["C:\\OfficeMCP\\office-com\\server.py"],
      "env": {
        "PYTHONUTF8": "1",
        "PYTHONIOENCODING": "utf-8"
      }
    }
  }
}

클라이언트를 다시 시작한 뒤 office_status 도구가 보이는지 확인하세요. 서버는 stdio로 통신합니다. 수동 실행하면 메시지를 기다리며 출력 없이 대기하는 것이 정상입니다.

경로와 저장 위치

문서와 이미지 경로는 가능한 한 Windows 절대 경로를 사용하세요. 새 파일을 저장할 폴더는 먼저 만들어 두어야 합니다. 이미 열린 문서를 편집하는 도구는 실제 파일을 바꿀 수 있으므로 중요한 원본은 복사본으로 작업하세요.

첫 실행 점검

  1. office_status를 호출해 브리지 연결 상태를 봅니다. 이 도구는 앱을 강제로 열지 않습니다.
  2. Word, PowerPoint, Excel에서 각각 테스트 파일을 열거나 도구로 새 파일을 만듭니다.
  3. doc_get_document_info, ppt_get_presentation_info, xl_get_workbook_info로 내용을 읽습니다.
  4. 테스트 파일에 작은 변경을 적용하고 해당 앱의 doc_save, ppt_save, xl_save를 호출합니다.
  5. Office 화면과 저장 파일을 확인합니다.

앱이 이미 실행 중이면 해당 인스턴스에 연결하고, 실행 중이지 않으면 첫 COM 호출에서 앱을 시작할 수 있습니다. 슬라이드·문단 번호는 1부터 시작합니다.

“C:\Work\draft.pptx를 열고 슬라이드 제목과 본문을 확인한 뒤,
3번 슬라이드의 제목만 바꾸고 저장해 줘.”

도구 결과는 보통 {"ok": true, "result": ...} 또는 {"ok": false, "error": ...} 형태입니다. 오류의 type과 message를 확인하세요.

문제 해결

증상확인할 내용
설치 중 wheel을 찾지 못함Python 3.11 64비트인지, wheelhouse/win_amd64_py311 폴더 전체를 복사했는지 확인합니다. 설치 명령에 --no-index가 있어야 합니다.
도구가 보이지 않음MCP 설정의 Python·server.py 절대 경로를 확인하고 클라이언트를 다시 시작합니다. verify-windows.py도 실행합니다.
BridgeUnavailable로컬 포트 8765 사용 여부를 확인합니다. 브리지는 첫 호출에 자동 시작됩니다. 포트를 바꿀 때는 OFFICE_BRIDGE_PORT를 동일하게 적용합니다.
ComConnectionError 또는 시간 초과Office가 설치되어 있는지, 저장·보안 확인 같은 대화상자가 열려 있는지 확인합니다. 대화상자를 닫고 다시 시도합니다.
DocumentNotFoundError파일·대상 폴더가 존재하는지, 문서가 열려 있는지, Windows 절대 경로인지 확인합니다.
PowerPoint 차트가 느림첫 차트 호출은 Excel이 함께 시작되어 시간이 걸릴 수 있습니다. 필요하면 브리지 시간 제한을 높이거나 Excel을 먼저 엽니다.
코드를 바꿨는데 반영되지 않음브리지는 MCP 클라이언트보다 오래 실행될 수 있습니다. 로컬 브리지 프로세스를 종료하고 클라이언트를 다시 시작합니다.

브리지는 기본적으로 localhost에서만 듣고 별도 인증이 없습니다. 외부 네트워크 인터페이스에 포트를 열지 마세요. 상세한 Office 특이 사항은 원본 오류·주의 사항에 있습니다.

범위와 출처

이 패키지의 확인 범위

모의 COM 테스트 367개가 통과했고, 동봉한 wheel만으로 Python 의존성이 해결되는 것을 확인했습니다. 실제 Office COM 실행과 PowerShell 설치는 Windows PC에서 최종 확인해야 합니다.
